# Room Grid Implementation Plan

> **Note on form.** This plan is deliberately compact: it was written to be executed immediately, in
> the session that produced it, rather than handed to an engineer with no context. It fixes the task
> boundaries, the exact interfaces between them, and the verification each one owes — the parts that
> stay useful. It does not restate the implementation as code blocks, which in that situation is
> transcription rather than planning.

**Goal:** A room's overview becomes one 4-column grid whose tiles declare their span, replacing four stacked `LazyVGrid`s.

**Spec:** `docs/superpowers/specs/2026-07-30-room-grid-design.md`

## Global constraints

- **Sequential packing, no backfill.** A gap stays a gap. 5b makes this sequence draggable and the order set must be the order seen.
- **Row height is measured** from the tallest single-row subview; `GlassTile`'s 66pt floor is the fallback when there is no single-row subview.
- **Nothing shrinks.** A tile may grow (a camera will, by ~30pt); no tile may get smaller than today.
- **`TileSpan` is a value**, clamped to the grid width, so a 4×1 or 4×2 needs no new case.
- Tests are Swift Testing. HavenCore: `cd Packages/HavenCore && swift test`. App: `xcodebuild test -scheme HavenApp -destination 'id=DC9ADC81-2C28-4C9D-89C6-7886DFBEB65C'` **from the repo root** — the shell's directory persists between commands, and running it from the package directory fails with "workspace HavenCore does not contain a scheme HavenApp".
- `xcodegen generate` from the repo root after adding a file.
- `timeout` does not exist on macOS.

## Task 1 — `TileSpan` and `GridPacking` (HavenCore)

**Files:** create `Packages/HavenCore/Sources/HavenCore/Curation/TileSpan.swift`, `Packages/HavenCore/Tests/HavenCoreTests/GridPackingTests.swift`

**Produces:** `TileSpan(columns:rows:)`, `TileSpan.default(for: Domain)`, `TileSpan.clamped(toWidth:)`, `GridPlacement(column:row:span:)`, `GridPacking.place(_:columns:)`, `GridPacking.rowCount(_:)`.

**Tests, each a case the layout would otherwise get wrong:**
1. A row of four 1×1s fills row 0 then wraps.
2. A 2-wide tile arriving at column 3 starts a new row, and **column 3 stays empty**.
3. A 2×2 occupies two rows; a following 1×1 goes beside it, not under it.
4. A 4-wide tile always starts a row.
5. A span wider than the grid is clamped, not dropped.
6. `default(for:)` for every `Domain` case — a `switch` with no `default` catches a new domain at compile time; this catches a wrong answer for an existing one.
7. `rowCount` counts the rows a 2×2 in the last position occupies.

**Verify:** HavenCore suite. **Commit.**

## Task 2 — `RoomGrid` (App, a SwiftUI `Layout`)

**Files:** create `App/DesignSystem/RoomGrid.swift`

**Produces:** `RoomGrid(columns:spacing:)` and `View.tileSpan(_:)` backed by a `LayoutValueKey`.

`sizeThatFits` measures every subview, derives the row height per the constraint above, asks `GridPacking` for placements, and returns the packed height. `placeSubviews` proposes each subview its cell exactly.

**Verify:** builds, and Task 4's renders. **Commit** with Task 3 if it does not stand alone.

---

## Task 3 — `RoomSectionView` uses it

**Files:** modify `App/Views/RoomSectionView.swift`, `App/Renderers/Tiles/CameraTile.swift`

- Four `[GridItem]` arrays and four grids become one ordered sequence of refs and one `RoomGrid`.
- Order is today's bands flattened: climate, miscellaneous, media, cameras.
- The **+** becomes a 1×1 at the end, retiring the "render the fourth grid even when empty so the + has somewhere to live" special case from sub-project 4.
- `CameraTile.square` drops its hard-coded 141; the grid owns that arithmetic now.

**Verify:** both suites; the app suite must be unchanged at 96 — this task changes layout, not behaviour.

## Task 4 — Look at it

**Files:** modify `App/Renderers/TileGallery.swift`

A page rendering the room shapes the packer is about: all 1×1s; one thermostat followed by lights (the gap-filling case); two cameras; all 2-wide tiles; and a room in configuration mode, where placeholders and the **+** must land in the same cells as the tiles they replace.

**And scrolled, not only at rest** — the room grid sits in a vertical scroll inside a horizontal pager, and every previous sub-project shipped a defect a static render could not show. Render a room taller than the screen and look at it part-scrolled.

**Verify:** renders. **Commit.**
